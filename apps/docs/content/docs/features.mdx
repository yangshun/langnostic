Translate localization files and documentation with less repetitive work.
Choose your AI provider, work with your project's file formats, and review
translations alongside your code.

<span id="ai-providers" />

## Bring your own AI

Choose the AI provider and model that suit your content, quality expectations,
and budget. Use your own account and credentials to manage translation usage
directly with your provider.

Short interface messages and long technical guides can call for different
trade-offs. Evaluate compatible models on your own content and choose the
balance of quality, speed, and cost that fits your project. AI usage follows
your provider's billing terms.

See [AI settings](/docs/configuration#ai-settings) for compatible providers and
setup.

## File format-agnostic

Langnostic can be extended to translate any file format whose content can be
represented as strings. Plugins extract the translatable content and write
translations back into the file's structure.

For example, translate your app's messages and its documentation as part of the
same workflow. The official plugins cover
[flat FormatJS JSON catalogs](/docs/plugins/formatjs) and
[Markdown/MDX documents](/docs/plugins/mdx), including frontmatter. More formats
are on the [roadmap](/docs/roadmap).

If your project uses another schema or file type, a custom plugin can add
support. This lets you adapt translation to your existing content pipeline.
Start with [Using plugins](/docs/plugins) for setup and extension options.

## Translate only what has changed

Updating a few messages or a section of documentation shouldn't require
translating everything again. Langnostic reuses existing translations and
focuses AI requests on content that needs work, helping reduce repeated work
and translation costs as your project evolves.

<span id="formatjs-catalogs" />

<span id="markdownmdx" />

For instance, the [Markdown plugin](/docs/plugins/mdx#mdx-change-detection) tracks
content by block. When you edit a block, it can translate that content and reuse
translations for unchanged blocks.

Each plugin defines how changes are detected and tracked. See the
[FormatJS](/docs/plugins/formatjs#formatjs-change-detection) and
[Markdown / MDX](/docs/plugins/mdx#mdx-change-detection) references for what
triggers translation and how to preserve existing work.

## Coordinate translation at scale

Adding several languages or translating a large documentation set can involve
many requests. Langnostic runs translation requests in parallel so you can
process more content without waiting for every request in sequence.

Adjust request size and the amount of work in progress to fit your model and
provider limits. For example, start with a smaller workload while trying a new
provider, then increase parallelism as you learn what your account can handle.
The same workflow can serve a small catalog or a growing set of translated
guides.

See [Configuration](/docs/configuration) for controls over request size and
parallelism.

## Preview and review your changes

Check the scope of a translation run before committing time or AI usage to it.
A dry run shows which files need work and how many strings are pending, making
it easier to spot an unexpected file or an overly broad selection before
translation starts.

Translations are written to your project's files, so you can inspect the diff,
edit wording, and commit changes alongside the code or documentation they belong
to. Use your usual review process to decide what is ready to ship.

See [CLI](/docs/cli) for previews and troubleshooting, and
[Workflows](/docs/workflows) for integrating translation into your development
process.
