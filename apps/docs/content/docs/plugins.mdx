Plugins read your file formats, identify pending content, provide translation
instructions, and write translated files. The CLI handles source discovery,
AI requests, batching, and progress reporting.

The official plugins support [FormatJS catalogs](/docs/plugins/formatjs) and
[Markdown/MDX documents](/docs/plugins/mdx).

## Install plugins

Install the CLI, your AI provider, and the plugins for the formats you use.
This example uses OpenAI and both official plugins:

```package-install
npm install langnostic @ai-sdk/openai @langnostic/plugin-formatjs @langnostic/plugin-mdx --save-dev
```

The CLI does not install plugins or provider packages for you. Make provider
credentials available before translating; the OpenAI provider reads
`OPENAI_API_KEY` from the environment or your project's `.env` file.

## Configure translation groups

Import each plugin's default factory and assign a new instance to each group.
This configuration translates a message catalog and MDX documents:

```typescript title="langnostic.config.ts"
import { openai } from '@ai-sdk/openai';
import FormatJSPlugin from '@langnostic/plugin-formatjs';
import MdxPlugin from '@langnostic/plugin-mdx';
import type { ConfigType } from 'langnostic';

export default {
  ai: {
    model: openai('gpt-6.1-sol'),
  },
  localeConfig: {
    source: 'en-US',
    target: ['zh-CN'],
  },
  groups: [
    {
      name: 'app-strings',
      plugin: FormatJSPlugin(),
      paths: [
        {
          source: './src/locales/en-US.json',
          target: './src/locales/{locale}.json',
        },
      ],
    },
    {
      name: 'docs',
      plugin: MdxPlugin(),
      paths: [
        {
          source: './docs/en-US/**/*.mdx',
          target: './docs/{locale}/**/*.mdx',
        },
      ],
    },
  ],
} satisfies ConfigType;
```

Each factory returns a `LangnosticPlugin`. A plugin instance stores its group's
tracked files and options, so create a separate instance for every group, even
when several groups use the same format.

Pass format-specific options to the factory. Put `paths`, `localeConfig`, and
`stringsPerRequest` on the group. See
[Configuration](/docs/configuration#translation-groups) for all group fields.

## Paths and locales

Set the default source and target locales in the top-level `localeConfig`.
A group can supply a complete locale override with its own `source` and `target`.

Paths are resolved from the directory where you run the CLI. Use `{locale}` in
the target pattern for each target locale, and matching wildcard captures to
retain source subdirectories or filenames. The CLI resolves these paths before
passing file metadata to the plugin.

See [path mappings](/docs/configuration#path-mappings) for supported patterns and
destination validation.

## Batching and concurrency

Plugins supply a default number of strings per request: **50** for FormatJS and
**20** for Markdown/MDX. Set a positive integer `stringsPerRequest` on a group to
override its plugin's default. This counts strings, not tokens or files; an MDX
string can be a whole document block.

The top-level `concurrencyLimit` controls concurrent AI requests across groups
and defaults to **5**. See [Configuration](/docs/configuration) for settings.

## Run and review

Preview pending file batches and string counts, then translate:

```bash
npx langnostic translate --dry-run
npx langnostic translate
```

A dry run makes no AI requests or file changes. It does not preview individual
strings or list maintenance-only changes such as removed IDs or reordered blocks.

Review the generated diff and validate messages, placeholders, Markdown, JSX,
and code examples with your application's tooling. Commit translated documents
with their MDX registries, and keep `.langnostic/` debug output out of version
control. See [Workflows](/docs/workflows) for review, retries, and CI integration.

## Official plugins

### FormatJS plugin

<span id="catalog-schema" />

The [FormatJS reference](/docs/plugins/formatjs#catalog-schema) describes flat
JSON string maps and descriptors with `defaultMessage` and `description`.

<span id="formatjs-change-detection" />

Its [change detection](/docs/plugins/formatjs#formatjs-change-detection) fills
missing target IDs and removes obsolete IDs. Source edits under an existing ID
do not trigger retranslation.

### Markdown/MDX plugin

<span id="frontmatter-options" />

The [Markdown / MDX reference](/docs/plugins/mdx#frontmatter-options) covers both
extensions and options for excluding frontmatter fields from AI requests.

<span id="mdx-change-detection" />

Read [MDX change detection](/docs/plugins/mdx#mdx-change-detection) for registry
requirements, structural edits, and cases that trigger full retranslation.

<span id="syntax-and-code-examples" />

The [syntax guidance](/docs/plugins/mdx#syntax-and-code-examples) explains
model-dependent preservation and formatting changes.

## Custom plugins

Implement `LangnosticPlugin` to add a format. The
[Plugin API reference](/docs/plugin-api) documents exported types, hook signatures,
argument and result shapes, and a
[complete plain-text plugin](/docs/plugin-api#complete-example).

### Lifecycle and writes

Discovery must leave files unchanged. Queue maintenance for `onTranslationStart()`
and write translated results in `onTranslationBatchComplete()`. See the
[hook reference](/docs/plugin-api#lifecycle) for call order, concurrency, and
failure behavior, and [Utilities](/docs/utilities) for normalization and atomic
write helpers.
