title: Philosophy
description: File ownership, provider choice, explicit workflows, and format-specific behavior.
---

Langnostic is built around files and explicit translation workflows. These
principles guide its current design and the [roadmap](/docs/roadmap).

## Keep content portable

Generated translations stay in the project's own files. They can be reviewed,
edited, committed, or consumed by compatible localization tooling without a
Langnostic-hosted translation store.

Portability still depends on format compatibility. Official plugins cover flat
string/FormatJS JSON catalogs and Markdown/MDX; other schemas need plugins.

## Make provider choice explicit

Configure a named provider and model using your own credentials. Choose
providers according to your content, quality expectations, availability, and
usage costs. Changing the model does not automatically replace existing
translations.

## Fit the project's workflow

Run translation before your application is built or deployed. Use existing
scripts, version control, review, and validation tools. Project configuration
controls file paths and locale groups rather than imposing a directory layout.

## Let plugins own format behavior

Each format has different units of translation and tracking requirements.
FormatJS compares IDs; MDX tracks block and frontmatter hashes. The
[plugin contract](/docs/plugin-api#lifecycle) separates read-only
discovery from file writes.

The documentation describes those differences rather than promising identical
change detection or preservation across formats. Model-generated text and syntax
still need review.
